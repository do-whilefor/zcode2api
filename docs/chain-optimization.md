# Go 请求链路优化与清理

日期：2026-10-29。

## 逻辑与开销

- 配置和请求对象使用递归拷贝，消除 JSON 编解码中转；整数保留原类型，嵌套数组和对象互不共享。
- 调度以一次联表查询读取账号及分组，在锁外解析模型能力、余额和到期状态。锁内只检查并发状态、按策略选出最佳空闲账号并预留名额；选取从排序改为线性比较，保留分组优先级、黏连和三种策略。
- 排队改为账号状态变化通知，避免每 100ms 重查数据库。保留每秒一次兜底，允许感知数据库外部修改。先取得通知代次再选账号，避免错过释放事件。
- 账号汇总一次聚合全池 24 小时快照，避免逐账号查询；公开账号视图不再重复读取和解密凭据，平台名称由原有专用逻辑统一提供。
- 上游正文、思考、签名和工具参数，以及 Responses 内容块，改为增长缓冲区。Chat 转发不再重复累积一份流文本和工具参数。
- Responses 在开始事件时预留输出位置，完成事件按原索引填入，去掉完成时的多轮遍历与排序。并发工具倒序结束仍保持输出顺序。
- 数据库扫描复用每次查询的接收缓冲，并预分配行对象；新增账号分组及快照时间索引。

未修改三协议端点、账号和密钥格式、10 秒全池限流窗口、首字后禁止重放，以及取消/超时边界。索引在启动时补齐，不清空现有表或凭据。

## 基准

同机 Windows amd64、Intel Core i5-1035G4，使用临时 SQLite 和合成数据，不请求真实上游。下表为本次修改前后各一次执行的观察值，硬件负载会影响结果：

| 场景 | 修改前耗时 | 修改后耗时 | 修改前分配 | 修改后分配 |
| --- | ---: | ---: | ---: | ---: |
| 配置快照 | 29.0 µs | 2.53 µs | 12,970 B / 197 次 | 2,576 B / 12 次 |
| 32 账号选取与释放 | 902.6 µs | 708.0 µs | 405,500 B / 5,348 次 | 232,388 B / 3,245 次 |
| 16 账号汇总 | 4,704.2 µs | 547.7 µs | 674,986 B / 8,576 次 | 212,122 B / 2,541 次 |

这些只反映本地处理开销，不能据此宣称模型生成速度提高相同比例。

```sh
go test ./internal/server -run '^$' -bench 'Benchmark(ConfigSnapshot|SelectAccount|AccountSummary)$' -benchmem
```

## 清理与依赖

失效的 Claude CLI 测试样例（含隔离配置）和过时的 Node 实施计划已移入本机 `data/migrations/cleanup-*`，从源码树移除。空后端目录、未使用的结构字段/辅助方法、测试占位变量和启动脚本旧 Node 兼容分支已清理。现有数据、备份和协议兼容快照保留。

`go mod tidy -diff` 未发现冗余声明。保留两个直接依赖：`modernc.org/sqlite` 提供免 C 编译器的 SQLite，`golang.org/x/sys` 提供 Windows 系统版本读取；其余显式间接依赖均由 SQLite 使用。不手工删除 Go 模块校验记录。

## 验证

`go test -race ./...`、`go vet ./...` 和控制台 5 项测试通过。新增回归覆盖递归拷贝隔离、整数精度、数据库等待不阻塞账号释放、通知广播、三种调度策略/黏连资格，以及工具并发完成时的 Responses 输出顺序。测试使用临时目录和本地模拟上游，不消耗真实生成额度。
